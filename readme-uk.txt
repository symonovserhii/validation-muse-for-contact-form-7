Власні правила валідації та повідомлення для Contact Form 7 — regex, довжина, required-if, для кожного поля, сумісність з CF7 6.x SWV, мультимовність.

== Description ==

**Validation Muse** дозволяє писати власні правила валідації та повідомлення про помилки для кожного поля Contact Form 7 — прямо в редакторі форми, для кожної форми та поля окремо. Без коду, без глобальних налаштувань, без JavaScript-хаків.

Більшість плагінів валідації CF7 перестали працювати, коли Contact Form 7 6.x представив **Schema-based Validation (SWV)**. Validation Muse запускає свої фільтри з пріоритетом 20 (після ядра CF7) і використовує Reflection, щоб замінити SWV-помилки для вже невалідних полів — тож ваш користувацький текст справді відображається на новому валідаційному рушії.

= Чому Validation Muse =

* **Сумісність з CF7 6.x SWV** — працює з новим Schema-based Validation, не лише зі старими хуками.
* **Власні правила Regex та довжини** — задавайте власні regex-патерни, мінімальну та максимальну довжину для поля, кожне зі своїм повідомленням про помилку.
* **Умовні правила "Required-If"** — поле стає обов'язковим лише коли заповнено/відмічено пов'язане поле.
* **Клієнтська SWV-інтеграція** — стандартні правила валідації (required, email, length) впроваджуються в нативний рушій SWV CF7 для миттєвого зворотного зв'язку на фронтенді з повною підтримкою доступності (A11y).
* **Імпорт/експорт наборів правил та шаблони** — експортуйте/імпортуйте правила валідації у JSON, копіюйте їх з інших форм, застосовуйте глобальні шаблони масово.
* **Токени-плейсхолдери** — використовуйте `{field_label}`, `{min}` та `{max}` у повідомленнях валідації для генерації динамічного тексту.
* **Per-form, per-field** — кожна форма зберігає свої повідомлення; немає глобального перевизначення.
* **Зберігається у post meta** — повідомлення живуть з формою, сумісні з дублюванням форми CF7 та сторонніми плагінами імпорту/експорту CF7.
* **Мультимовність через WPML, Polylang та Flavor** — перекладає правила через стандартні хуки WPML/Polylang, а також показує мовні таби + кнопку AI Translate в один клік, коли активний Flavor.
* **Дружній до розробників** — хуки розширюваності `vmcf7_loaded` та `vmcf7_validation_tag_types` дозволяють додавати власні типи полів; фільтри `vmcf7_message`, `vmcf7_default_message`, `vmcf7_placeholders` та `vmcf7_field_label` дозволяють читати повідомлення, задавати типові повідомлення для всього сайту та додавати власні `{tokens}`.
* **Легкий** — без admin-роздуття, без трекінгу, без апселів.

= Підтримувані типи полів =

* Повідомлення про обов'язкові поля: будь-який required-тег (`text`, `textarea`, `select`, `checkbox`, `radio`, `file` тощо).
* Повідомлення про невалідний формат: `email`, `url`, `tel`, `number` (включно з `range`), `date` та `time`.
* Власні повідомлення про помилку при невдалій валідації: `file` (перевірка розміру/типу), `acceptance` (чекбокс не відмічено) та `quiz` (неправильна відповідь).
* HTML усередині повідомлень дозволений і очищується через `wp_kses_post()`.
* Власні правила Regex та Мін/Макс довжини доступні для всіх типів полів, окрім `file`.

= Переклади =

Плагін постачається з `.pot`-файлом і вже перекладений німецькою, іспанською, французькою, італійською, японською, польською, португальською (Бразилія), російською та українською. [Допоможіть перекласти на свою мову.](https://translate.wordpress.org/projects/wp-plugins/validation-muse-for-contact-form-7)

== Installation ==

1. Встановіть з **Плагіни → Додати новий** і знайдіть *Validation Muse for Contact Form 7*, або завантажте папку `validation-muse-for-contact-form-7` до `/wp-content/plugins/`.
2. Активуйте плагін. Contact Form 7 має бути активним — Validation Muse автоматично деактивується із сповіщенням, якщо CF7 відсутній.
3. Відредагуйте будь-яку форму Contact Form 7, відкрийте вкладку **Користувацька валідація**, увімкніть її та напишіть свої повідомлення.
4. (Опційно) Встановіть плагін перекладу Flavor для перекладу повідомлень за мовами з AI-асистенцією.

== Frequently Asked Questions ==

= Чи працює це з Contact Form 7 6.x та Schema-based Validation (SWV)? =

Так. Починаючи з версії 1.3.0, Validation Muse чіпляється на пріоритет 20 (після ядра CF7) і використовує Reflection для заміни SWV-помилок для вже невалідних полів. Починаючи з 1.6.1, стандартні правила (required, email/url/tel/number/date/time, мін/макс довжина) також впроваджуються прямо у власну SWV-схему CF7, тож клієнтська (фронтенд JS) валідація миттєво показує ваші повідомлення — через нативний рушій валідації CF7, без жодного додаткового скрипта цього плагіна.

= Чим це відрізняється від інших плагінів валідації CF7? =

Validation Muse — єдиний плагін валідації CF7, який (1) сумісний з CF7 6.x SWV з коробки — як на сервері, так і у власній клієнтській валідації CF7, (2) зберігає повідомлення у post meta форми, тож вони живуть з формою (сумісно з дублюванням форми CF7 та плагінами імпорту/експорту), та (3) підтримує повідомлення для кожної мови через WPML, Polylang або плагін перекладу Flavor (з AI-перекладом в один клік).

= Чи можна перекладати повідомлення валідації за мовами? =

Так. WPML (String Translation) і Polylang підтримуються нативно: ваші повідомлення реєструються для перекладу під час кожного збереження форми, а вкладка **Користувацька валідація** веде на екран, де ви їх перекладаєте. З плагіном перекладу Flavor Validation Muse додатково показує мовні таби в редакторі форми та кнопку *AI Translate*; ці переклади зберігаються в базі даних Flavor, а видалення Validation Muse очищує їх.

= Які типи полів підтримують власні повідомлення про невірний формат або помилку валідації? =

* `email`, `url`, `tel`, `number` (включно з `range`), `date` та `time` підтримують власні повідомлення про невірний формат.
* `file` підтримує власні повідомлення про помилку валідації розміру/типу файлу.
* `acceptance` підтримує власні повідомлення про помилку, коли чекбокс не прийнято.
* `quiz` підтримує власні повідомлення про помилку, коли відповідь неправильна.
* Будь-яке обов'язкове поле будь-якого типу може мати власне повідомлення про обов'язковість.

= Де зберігаються повідомлення? =

У post meta кожної форми. Вони живуть з формою, тому дублювання форми (вбудоване в CF7) зберігає повідомлення. CF7 не має нативного експорту, але сторонні плагіни імпорту/експорту CF7 читають post meta — тож міграції між сайтами працюють без окремого кроку імпорту.

= Чи можна використовувати HTML у повідомленнях валідації? =

Так, базовий HTML дозволений і очищується через `wp_kses_post()`.

= Чи потребує цей плагін Contact Form 7? =

Так. CF7 має бути встановлений та активний. Плагін показує admin-сповіщення і самодеактивується, якщо CF7 відсутній.

= Чи є сторінка налаштувань? =

Ні. Конфігурація живе всередині кожної форми, на вкладці **Користувацька валідація**. Глобальної сторінки налаштувань немає за дизайном — кожна форма зберігає свої повідомлення.

= Чи трекає або відсилає плагін якісь дані? =

Ні. Validation Muse не робить жодних зовнішніх запитів. Опційна кнопка AI Translate (інтеграція з Flavor) маршрутизується через власного провайдера Flavor.
