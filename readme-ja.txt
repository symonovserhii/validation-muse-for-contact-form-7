Contact Form 7 用の独自の検証ルールとメッセージ — 正規表現、文字数、条件付き必須、項目ごとの設定、CF7 6.x SWV 対応、多言語対応。

== Description ==

**Validation Muse** を使うと、Contact Form 7 のすべての項目に独自の検証ルールとエラーメッセージを設定できます — フォームエディター内で、フォームごと、項目ごとに直接設定します。コードも、全体設定ページも、JavaScript のハックも不要です。

Contact Form 7 6.x で **Schema-based Validation (SWV)** が導入されたとき、多くの CF7 検証プラグインが動作しなくなりました。Validation Muse はフィルターを優先度 20 (CF7 コアの後) で実行し、Reflection を使ってすでに無効と判定された項目の SWV エラーテキストを置き換えるため、新しい検証エンジンでも独自の文言が確実に表示されます。

= Validation Muse を選ぶ理由 =

* **CF7 6.x SWV 対応** — 従来のフックだけでなく、新しい Schema-based Validation エンジンでも動作します。
* **独自の正規表現ルールと文字数ルール** — 項目ごとに独自の正規表現パターン、最小文字数、最大文字数のルールを定義し、それぞれに専用のエラーメッセージを設定できます。
* **条件付き必須 (Required-If) ルール** — 関連する項目が入力またはチェックされている場合にのみ、項目を必須にします。
* **クライアント側の SWV 連携** — 標準の検証ルール (必須、メール、文字数) を CF7 ネイティブの SWV エンジンに組み込み、アクセシビリティ (A11y) に完全対応した即時のフロントエンドフィードバックを実現します。
* **ルールセットのインポート / エクスポートとテンプレート** — 検証ルールを JSON としてエクスポート / インポートしたり、他のフォームからコピーしたり、共通のテンプレートを一括適用したりできます。
* **プレースホルダートークン** — 検証メッセージ内で `{field_label}`、`{min}`、`{max}` を使って動的な文言を生成できます。
* **フォームごと、項目ごと** — 各フォームがそれぞれのメッセージを保持します。全体を上書きする設定はありません。
* **投稿メタに保存** — メッセージはフォームと一緒に保存されるため、CF7 のフォーム複製やサードパーティ製の CF7 インポート / エクスポートプラグインと互換性があります。
* **WPML、Polylang & Flavor による多言語対応** — WPML / Polylang の標準フックを使ってルールを翻訳します。Flavor が有効な場合は、言語タブとワンクリックの AI Translate も利用できます。
* **開発者にやさしい設計** — 拡張用フック `vmcf7_loaded` と `vmcf7_validation_tag_types` で独自の項目タイプを追加できます。`vmcf7_message`、`vmcf7_default_message`、`vmcf7_placeholders`、`vmcf7_field_label` フィルターを使えば、メッセージの取得、サイト全体のデフォルト設定、独自の `{tokens}` の追加が可能です。
* **軽量** — 管理画面の肥大化なし、トラッキングなし、アップセルなし。

= 対応している項目タイプ =

* 必須項目のメッセージ: すべての必須タグ (`text`、`textarea`、`select`、`checkbox`、`radio`、`file` など)。
* 形式エラーのメッセージ: `email`、`url`、`tel`、`number` (`range` を含む)、`date`、`time` の各項目。
* 検証失敗時の独自エラーメッセージ: `file` (サイズ / 種類のチェック)、`acceptance` (未チェック / 未承諾の状態)、`quiz` (不正解)。
* メッセージ内で HTML を使用でき、`wp_kses_post()` でサニタイズされます。
* 独自の正規表現ルールと最小 / 最大文字数ルールは、`file` を除くすべての項目タイプで利用できます。

= 翻訳 =

このプラグインには `.pot` ファイルが同梱されており、すでに日本語、ドイツ語、スペイン語、フランス語、イタリア語、ポーランド語、ポルトガル語 (ブラジル)、ロシア語、ウクライナ語に翻訳されています。[あなたの言語への翻訳にご協力ください。](https://translate.wordpress.org/projects/wp-plugins/validation-muse-for-contact-form-7)

== Installation ==

1. **プラグイン → 新規プラグインを追加** から *Validation Muse for Contact Form 7* を検索してインストールするか、`validation-muse-for-contact-form-7` フォルダーを `/wp-content/plugins/` にアップロードします。
2. プラグインを有効化します。Contact Form 7 があらかじめ有効化されている必要があります — 有効でない場合、Validation Muse は管理画面に通知を表示して自動的に無効化されます。
3. 任意の Contact Form 7 フォームを編集し、**カスタム検証**タブを開いて有効にし、メッセージを入力します。
4. (任意) Flavor 翻訳プラグインをインストールすると、AI の支援を受けて言語ごとにメッセージを翻訳できます。

== Frequently Asked Questions ==

= Contact Form 7 6.x と Schema-based Validation (SWV) で動作しますか ? =

はい。バージョン 1.3.0 以降、Validation Muse は優先度 20 (CF7 コアの後) でフックし、Reflection を使ってすでに無効と判定された項目の SWV エラーテキストを置き換えます。1.6.1 以降は、標準ルール (必須、email/url/tel/number/date/time、最小 / 最大文字数) も CF7 自体の SWV スキーマに直接組み込まれるため、クライアント側 (フロントエンド JS) の検証でも独自のメッセージが即座に表示されます — このプラグインが追加のスクリプトを読み込むことなく、CF7 ネイティブの検証エンジンを通じて行われます。

= 他の CF7 検証プラグインとの違いは何ですか ? =

Validation Muse は、次の 3 点を満たす唯一の CF7 検証プラグインです。(1) そのままで CF7 6.x SWV に対応 — サーバー側でも CF7 自体のクライアント側検証でも動作します。(2) メッセージをフォームの投稿メタに保存するため、メッセージがフォームと一緒に保持されます (CF7 のフォーム複製やインポート / エクスポートプラグインと互換)。(3) WPML、Polylang、または Flavor 翻訳プラグイン (ワンクリックの AI 翻訳付き) による言語ごとのメッセージに対応しています。

= 検証メッセージを言語ごとに翻訳できますか ? =

はい。WPML (String Translation) と Polylang にネイティブ対応しています。フォームを保存するたびにメッセージが翻訳用に登録され、**カスタム検証**タブから翻訳画面へのリンクが表示されます。Flavor 翻訳プラグインを使用している場合は、フォームエディターに言語タブと *AI Translate* ボタンも表示されます。その翻訳は Flavor のデータベースに保存され、Validation Muse をアンインストールすると削除されます。

= 形式エラーや検証失敗時の独自メッセージに対応している項目タイプはどれですか ? =

* `email`、`url`、`tel`、`number` (`range` を含む)、`date`、`time` は、形式エラーの独自メッセージに対応しています。
* `file` は、ファイルのサイズ / 種類の検証エラーの独自メッセージに対応しています。
* `acceptance` は、チェックボックスが承諾されていない場合の独自エラーメッセージに対応しています。
* `quiz` は、答えが間違っている場合の独自エラーメッセージに対応しています。
* タイプを問わず、すべての必須項目に独自の必須項目メッセージを設定できます。

= メッセージはどこに保存されますか ? =

各フォームの投稿メタに保存されます。メッセージはフォームと一緒に保持されるため、フォームを複製 (CF7 の標準機能) してもメッセージはそのまま残ります。CF7 にはネイティブのエクスポート機能はありませんが、サードパーティ製の CF7 インポート / エクスポートプラグインは投稿メタを読み込むため、別途インポート作業をしなくてもサイト間の移行が可能です。

= 検証メッセージで HTML を使用できますか ? =

はい。基本的な HTML を使用でき、`wp_kses_post()` でサニタイズされます。

= このプラグインには Contact Form 7 が必要ですか ? =

はい。CF7 がインストールされ、有効化されている必要があります。CF7 が見つからない場合、プラグインは管理画面に通知を表示して自動的に無効化されます。

= 設定ページはありますか ? =

いいえ。設定は各フォーム内の**カスタム検証**タブで行います。意図的に全体設定ページは設けていません — 各フォームがそれぞれのメッセージを保持します。

= このプラグインはデータを追跡または送信しますか ? =

いいえ。Validation Muse は外部へのリクエストを一切行いません。任意の AI Translate ボタン (Flavor 連携) は、Flavor 側で設定されたプロバイダーを経由します。

= 1.8.0 =

* 新機能: コピー、バックアップ、テンプレート、「すべてのフォームで使う」の各ツールをグループ化して説明を付けました。確認はその場で求められ、結果はブラウザーのポップアップではなくパネル内に表示されます。

* 新機能: 日本語、イタリア語、ポーランド語の翻訳を追加しました。
* 修正: 何も変更していないのに、Contact Form 7 エディターが「このサイトを離れますか ? 行った変更が保存されない可能性があります」と確認する問題を修正しました。

* 修正: 無効なパターンがすべての回答を拒否することはなくなりました。チェックボックスや複数選択に設定したパターンや文字数のルールが、送信時にエラーを引き起こすこともなくなりました。
* 修正: フォームのルールを同じフォームにコピーしても、ルールが消えなくなりました。ルールセットのツールは、ユーザーが編集できる Contact Form 7 フォームのみを受け付け、インポートファイルは内容の検査とサイズ制限が行われます。
* 修正: WPML / Polylang に各メッセージが 1 回分の保存だけ遅れて渡されていた問題、Polylang の翻訳画面にメッセージが表示されなかった問題、その後に二重に表示された問題を修正しました。
* 修正: 必須項目の独自メッセージが承諾確認チェックボックスにも適用されるようになりました。条件付き必須は、相手の項目名に大文字が含まれていても動作します。
