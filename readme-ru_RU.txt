Собственные правила валидации и сообщения для Contact Form 7 — regex, длина, required-if, для каждого поля, совместимость с CF7 6.x SWV, мультиязычность.

== Description ==

**Validation Muse** позволяет писать собственные правила валидации и сообщения об ошибках для каждого поля Contact Form 7 — прямо в редакторе формы, для каждой формы и поля отдельно. Без кода, без глобальных настроек, без JavaScript-хаков.

Большинство плагинов валидации CF7 перестали работать, когда Contact Form 7 6.x представил **Schema-based Validation (SWV)**. Validation Muse запускает свои фильтры с приоритетом 20 (после ядра CF7) и использует Reflection, чтобы заменить SWV-ошибки для уже невалидных полей — поэтому ваш пользовательский текст действительно отображается на новом валидационном движке.

= Почему Validation Muse =

* **Совместимость с CF7 6.x SWV** — работает с новой Schema-based Validation, не только со старыми хуками.
* **Собственные правила Regex и длины** — задавайте свои regex-паттерны, минимальную и максимальную длину по полю, каждое со своим сообщением об ошибке.
* **Условные правила "Required-If"** — поле становится обязательным только когда заполнено/отмечено связанное поле.
* **Клиентская SWV-интеграция** — стандартные правила валидации (required, email, length) внедряются в нативный движок SWV CF7 для мгновенной обратной связи на фронтенде с полной поддержкой доступности (A11y).
* **Импорт/экспорт наборов правил и шаблоны** — экспортируйте/импортируйте правила валидации в JSON, копируйте их из других форм, применяйте глобальные шаблоны массово.
* **Токены-плейсхолдеры** — используйте `{field_label}`, `{min}` и `{max}` в сообщениях валидации для генерации динамического текста.
* **Per-form, per-field** — каждая форма хранит свои сообщения; нет глобального переопределения.
* **Хранится в post meta** — сообщения живут с формой, совместимы с дублированием формы CF7 и сторонними плагинами импорта/экспорта CF7.
* **Мультиязычность через WPML, Polylang и Flavor** — переводит правила через стандартные хуки WPML/Polylang, а также показывает языковые табы + кнопку AI Translate в один клик, когда активен Flavor.
* **Дружественен к разработчикам** — хуки расширяемости `vmcf7_loaded` и `vmcf7_validation_tag_types` позволяют добавлять собственные типы полей; фильтры `vmcf7_message`, `vmcf7_default_message`, `vmcf7_placeholders` и `vmcf7_field_label` позволяют читать сообщения, задавать сообщения по умолчанию для всего сайта и добавлять собственные `{tokens}`.
* **Лёгкий** — без admin-раздутия, без трекинга, без апселов.

= Поддерживаемые типы полей =

* Сообщения для обязательных полей: любой required-тег (`text`, `textarea`, `select`, `checkbox`, `radio`, `file` и т.д.).
* Сообщения о невалидном формате: `email`, `url`, `tel`, `number` (включая `range`), `date` и `time`.
* Собственные сообщения об ошибке при неудачной валидации: `file` (проверка размера/типа), `acceptance` (чекбокс не отмечен) и `quiz` (неверный ответ).
* HTML внутри сообщений разрешён и очищается через `wp_kses_post()`.
* Собственные правила Regex и Мин/Макс длины доступны для всех типов полей, кроме `file`.

= Переводы =

Плагин поставляется с `.pot`-файлом и уже переведён на немецкий, испанский, французский, итальянский, японский, польский, португальский (Бразилия), русский и украинский. [Помогите перевести на ваш язык.](https://translate.wordpress.org/projects/wp-plugins/validation-muse-for-contact-form-7)

== Installation ==

1. Установите из **Плагины → Добавить новый**, найдя *Validation Muse for Contact Form 7*, или загрузите папку `validation-muse-for-contact-form-7` в `/wp-content/plugins/`.
2. Активируйте плагин. Contact Form 7 должен быть активен — Validation Muse автоматически деактивируется с уведомлением, если CF7 отсутствует.
3. Откройте любую форму Contact Form 7, перейдите на вкладку **Пользовательская валидация**, включите её и напишите свои сообщения.
4. (Опционально) Установите плагин перевода Flavor для перевода сообщений по языкам с AI-помощью.

== Frequently Asked Questions ==

= Работает ли это с Contact Form 7 6.x и Schema-based Validation (SWV)? =

Да. Начиная с версии 1.3.0, Validation Muse цепляется на приоритет 20 (после ядра CF7) и использует Reflection для замены SWV-ошибок для уже невалидных полей. Начиная с 1.6.1, стандартные правила (required, email/url/tel/number/date/time, мин/макс длина) также внедряются прямо в собственную SWV-схему CF7, поэтому клиентская (фронтенд JS) валидация мгновенно показывает ваши сообщения — через нативный движок валидации CF7, без какого-либо дополнительного скрипта этого плагина.

= Чем это отличается от других плагинов валидации CF7? =

Validation Muse — единственный плагин валидации CF7, который (1) совместим с CF7 6.x SWV из коробки — как на сервере, так и в собственной клиентской валидации CF7, (2) хранит сообщения в post meta формы, поэтому они живут с формой (совместимо с дублированием формы CF7 и плагинами импорта/экспорта), и (3) поддерживает сообщения для каждого языка через WPML, Polylang или плагин перевода Flavor (с AI-переводом в один клик).

= Можно ли переводить сообщения валидации по языкам? =

Да. WPML (String Translation) и Polylang поддерживаются нативно: ваши сообщения регистрируются для перевода при каждом сохранении формы, а вкладка **Пользовательская валидация** ведёт на экран, где вы их переводите. С плагином перевода Flavor Validation Muse дополнительно показывает языковые табы в редакторе формы и кнопку *AI Translate*; эти переводы хранятся в БД Flavor, а удаление Validation Muse очищает их.

= Какие типы полей поддерживают собственные сообщения о неверном формате или ошибке валидации? =

* `email`, `url`, `tel`, `number` (включая `range`), `date` и `time` поддерживают собственные сообщения о неверном формате.
* `file` поддерживает собственные сообщения об ошибке валидации размера/типа файла.
* `acceptance` поддерживает собственные сообщения об ошибке, когда чекбокс не отмечен.
* `quiz` поддерживает собственные сообщения об ошибке, когда ответ неверный.
* Любое обязательное поле любого типа может иметь собственное сообщение об обязательности.

= Где хранятся сообщения? =

В post meta каждой формы. Они живут с формой, поэтому дублирование формы (встроено в CF7) сохраняет сообщения. CF7 не имеет нативного экспорта, но сторонние плагины импорта/экспорта CF7 читают post meta — поэтому миграции между сайтами работают без отдельного шага импорта.

= Можно ли использовать HTML в сообщениях валидации? =

Да, базовый HTML разрешён и очищается через `wp_kses_post()`.

= Требует ли этот плагин Contact Form 7? =

Да. CF7 должен быть установлен и активен. Плагин показывает admin-уведомление и самодеактивируется, если CF7 отсутствует.

= Есть ли страница настроек? =

Нет. Конфигурация живёт внутри каждой формы, на вкладке **Пользовательская валидация**. Глобальной страницы настроек нет по дизайну — каждая форма хранит свои сообщения.

= Трекает или отправляет ли плагин какие-либо данные? =

Нет. Validation Muse не делает никаких внешних запросов. Опциональная кнопка AI Translate (интеграция с Flavor) маршрутизируется через собственного провайдера Flavor.
